WHY ARENA ALLOCATION SHOWED MINIMAL IMPROVEMENT
═══════════════════════════════════════════════════════════════

AST Node allocations: Only 5 samples (2.8% of runtime)
Arena optimization: Successfully eliminated these
Result: 0.2% improvement (within measurement variance)

The optimization worked perfectly but targeted the wrong bottleneck.
The real allocation overhead is in:
  1. Function::Args vectors (14.7%)
  2. Hash table structures (16.4%)
  3. Not AST nodes (2.8%)

This is a classic case of "measure before optimizing" - we made
an educated guess about the bottleneck (heap allocations for nodes)
which turned out to be correct in principle but wrong in magnitude.
